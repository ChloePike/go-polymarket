# Contributing

Patches are welcome. This file is what a reviewer will hold a change to, so
it is worth reading before writing much.

## The gates

Four commands. All four are green before a commit, and CI runs the same ones.

```
gofmt -l .        # must print nothing
go build ./...
go vet ./...
go test -race ./...
```

No test in this repository touches the network. Golden vectors and
`httptest` servers cover everything, so a red test is a real failure and not
a flaky one.

## Commits and pull-request titles

Conventional-commit prefixes, then what changes, in the imperative. CI checks
the pull-request title against this list:

| Prefix | For |
|---|---|
| `feat:` | new behaviour a caller can reach |
| `fix:` | behaviour that was wrong |
| `docs:` | documentation only |
| `refactor:` | same behaviour, different code |
| `test:` | tests only |
| `perf:` | same behaviour, faster |
| `chore:` | build, CI, repository furniture |

Add `!` before the colon for a change that breaks callers — `feat!:` — and
label the pull request `breaking change`.

One logical change per commit. A pull request may carry several, but not a
backlog: a reviewer reading `fix: …` should find only that fix in the diff.

Say **why** in the body. The diff already says what.

## The rules that are not style

These four exist because breaking them costs money or costs a reader, and
none of them is negotiable in review.

**Every struct type is declared and named.** No `var out struct{...}`, no
`[]struct{...}{...}` test table, no `type foo struct` inside a function.
Declare it at package level with a doc comment. A response shape written
inline at one call site is a shape nobody else can decode, and CI rejects
one. This applies to tests: a table-driven test declares its case type.

**No `float64` where an amount, a price or a size flows.** Money is
`math/big.Rat` and integer strings on the wire, six-decimal fixed point.
`0.29 * 100` is `28.999999999999996`, and an order's amounts are covered by a
signature — a rounding artefact is a signed commitment to the wrong number.
The one exception is the pre-trade fee estimate, which the protocol itself
defines with a fractional exponent; it is advisory and never signed.

**Clean-room.** Never paste third-party source into this tree. Read the
official TypeScript client and `Polymarket/go-order-utils` to learn how the
protocol works; transcribe constants and layouts, write the Go yourself.
Every new file starts with:

```go
// SPDX-License-Identifier: GPL-3.0-or-later
// Copyright (C) 2026 ChloePike
```

**Signing and amount changes need golden vectors.** `testdata/vectors.json`
is the observable output of the official SDK, regenerated by
`testdata/gen-vectors.mjs`. It pins order digests and signatures, level-1
payloads, level-2 HMACs, and thousands of limit- and market-order amounts. A
change to signing or amounts that no golden test covers does not land, and
"the existing tests still pass" is not the same thing — a vector that did not
change is a vector that did not exercise the change.

If you are touching `internal/eip712`, `signer.go`, `auth.go`,
`typeddata.go`, `internal/amount` or `order.go`, expect an adversarial
review: the field order, the digest layout, the rounding direction and the
byte order of a signature will each be argued against.

### The eleven-field trap

The signed `Order` struct has **eleven** fields. The wire JSON also carries
`taker` and `expiration`, and **neither is signed**. Signing thirteen fields
produces a valid-looking signature the exchange rejects, and nothing local
catches it.

## Comments

Go convention, kept strictly, because this is a library.

- A doc comment on every exported identifier, starting with its name. Named
  struct types included.
- A package doc on one file per package.
- Comment the protocol **why**: which constant the spec fixes, why a rounding
  goes one direction, why a bound exists. A reader cannot derive those.
- Do not narrate the code (`// increment i`), do not write diff history
  (`// fixes the old bug where …` — that is the commit message), and do not
  restate a type.

## Tests, and money

Point a client at an `httptest.Server` with `clob.WithHost(srv.URL)`. Every
read endpoint is public, so a staging environment for market data is just
production with no key.

`go run ./examples/authcheck` proves the whole signing stack against
production for free: it creates a throwaway key, exchanges it for real
credentials, spends them, and confirms a corrupted signature is rejected. Run
it after touching the signing path. It is not in CI, because it leaves a
credential on the server each time.

**Do not put a key anywhere near this repository.** Not in a source file, not
in a test, not in a fixture, not in a commit message. Credentials come from
the environment. Examples stay read-only: nothing in `examples/` places or
cancels an order.

There is no Polymarket testnet. A change that can only be verified by trading
cannot be verified by CI, and should say so in its pull request.

## Dependencies

Three, all pure Go, no cgo:

| Module | Why |
|---|---|
| `golang.org/x/crypto/sha3` | Keccak-256. The standard library's `crypto/sha3` is FIPS-202 and pads differently — it is not interchangeable. |
| `github.com/decred/dcrd/dcrec/secp256k1/v4` | Signing. This is the library go-ethereum's own pure-Go path wraps, so signatures are identical for three modules in `go.sum` instead of about 140. |
| `github.com/coder/websocket` | The streaming feeds. Zero transitive dependencies. |

A fourth needs to be argued for in an issue before the pull request. A
dependency is a supply chain, and this library signs transactions.

## Labels

`.github/labels.yml` is the source of truth; `.github/sync-labels.sh` applies
it. Two are worth knowing about:

- **`moves money`** — the change can cost somebody funds. It gets an
  adversarial review, not a read-through.
- **`needs golden vector`** — signing or amount math moved and no vector
  covers it. The pull request is not mergeable while this is on it.
